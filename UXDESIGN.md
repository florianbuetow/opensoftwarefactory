# Factory UI design system

Operate surface. Restrained color. System sans. 8px grid. Two neutral layers. One accent. Fixed state vocabulary.

## Non-negotiables

- Vanilla HTML/CSS/JS, no build step, no external resources, dependency-free Go server.
- Light and dark themes both first class.

## Brand commitments

- Mode: Operate. Earned familiarity over expression. The tool disappears into the task.
- Language: the factory's own words (workflow, step, run, trace, artifact, gate, agent, policy, collection, template). No "intake" in UI chrome; intake is just one agent.
- Identity carried by precise details: station-like step tiles, a run as a sequence of artifacts, one accent for action and selection, state colors with fixed meanings.

## Scene

An engineer at a desk, daytime, two monitors, the factory UI open for hours next to a terminal. Light theme is the default; dark theme follows the OS and is equally finished.

## Type

- Family: `-apple-system, "Segoe UI", system-ui, sans-serif`. Mono (`ui-monospace, SF Mono, Menlo, monospace`) only for ids, code, logs, and JSON, never as a costume; any other artifact text (Markdown, plain text) reads as prose wherever it is shown, Blobstore included, without the blank lines a model may put around it, its lines at most about 75 characters (paragraphs, lists, quotes and headings; tables and code keep the full width).
- Scale: 12 (labels, table headers), 13 (meta lines, inline links such as View trace, code), 14 (body, controls, tables, section titles such as Steps or System prompt (systemprompt.md)), 16 (panel titles), 18 (a decision question), 24 (dialog title). Weights 400/500/600. Line height 1.45 body, 1.25 titles.
- Ids are shortened in the middle (`7dcf…3045`) with the full id in a tooltip and a copy affordance; people never read a UUID to navigate.

## Color

- Light: canvas `#f4f6f8`, panel `#ffffff`, rail `#eceff3`, line `#d9dee6`, text `#161b24`, muted `#5b6675`.
- Dark: canvas `#12161c`, panel `#1a1f27`, rail `#151a21`, line `#2a3140`, text `#e7ebf2`, muted `#9aa5b5`.
- Accent `#2f6fde` (light) / `#6b9cf5` (dark): primary action, selection, focus ring. Nothing else is accent. Every control shows the focus ring to the keyboard (`:focus-visible`), the Sidebar and Detail toggles included; a click leaves none.
- States, same hue in both themes: running `#b7791f` (amber), done `#1f8a4c` (green), failed `#c23a3a` (red), waiting `#7c3aed` (violet), idle `muted`. A state is a filled dot plus a word; never color alone. Blocked (a run an agent ended with report_blocked) is a state of its own in the waiting hue, with a hollow dot, never the failed one: a person has to clear the way. Kubernetes states in Cluster use the same chips: Running and Ready green, Pending amber, failures red. In the Cluster sidebar a deployment short of replicas reads "Not ready" (none ready) or "Starting" (some), in the failed colour, its counts in its tooltip ("tool-gateway: 0 of 1 replicas ready"); a node that is not ready reads "Not ready"; never a bare count such as "0/1".
- Contrast: all text, placeholders included, meets 4.5:1 in both themes; placeholders use muted, never the browser grey. Only the decorative "·" separators in a meta line are fainter.
- Warnings use orange text (`#a44900` in light and `#f5a461` in dark) and always show the word **Warning**. A tool call that returns truncated output keeps its completed state and shows the warning in the event details.

## Layout

- App shell: 56px top bar with the rail background, spanning the logo: logo + product name at the left, the page menu (Main, Factory, Tasks, Connectors, Context; each opens a click menu of pages, and the active group is underlined) centred on the page, not between the logo and the chip, and the "Acting as" chip at the right, with, left of it while a service (a cluster deployment, checked every 10 s) is not ready, a Failed chip naming it ("tool-gateway not ready", or "2 services not ready"; the tooltip lists them with ready/desired) that opens Cluster, and left of that the trace ID jump, a small field ("Trace ID…", focused by /): Enter opens the run whose ID starts with what was typed (at least 4 characters, case and dashes ignored; a full ID opens even before the run list knows it), or says "3 runs match: type more of the ID" or "No run has that trace ID"; Escape clears it, and a narrow top bar drops it before the menu; while it is empty it is outlined red on the pages whose actions record the acting person (Workflows, Decisions, Agents, Policies, Blobstore), never on Runs, MCP Gateway, Connectors, or Cluster. No page title anywhere: the active menu item is the title. The browser tab shows the logo as its icon. Content fills the rest; each page clips itself (the window never scrolls as a whole), and the content area clips nothing, so the toggles row over it is never cut off.
- Insets: every section in a detail or content panel is padded 24 px on all sides, and nothing inside adds a margin at its bottom edge; a block inside an inset section (Blobstore's references and prompt evidence above the document) adds no inset of its own, so it lines up with what follows, 16 px above it. Tables in the middle column run edge to edge. Agents and Policies files stack without dividers, 24 px apart, with 24 px below the last one or the Save row, like the prompt and config in the node panel. Columns are separated by a single 1 px line; the panel at the window's right edge draws none.
- Panels have a 48px header: title (16/600) left, actions right. One primary button per page, at most, in the top bar or panel header, never squeezed beside a title.
- Tables: 14px, 40px rows, header 12/600 muted uppercase is forbidden; header is 12/600 muted sentence case. Numbers (sizes, counts) right-aligned; times left-aligned like text. A cut-off cell shows its full text as a tooltip on hover; a row (or control) the keyboard focuses shows the full text of what is cut off in it in a tooltip under it, which describes it, until focus leaves or Escape. In a middle column narrower than 420 px, optional columns give way (Workflow and By on Decisions, Creator on Blobstore) and the name column shrinks, header included, so no column leaves the screen. On Runs, Failure gives way first, in a middle column under 640 px, header included (the row keeps its red tint, its state, and the failure as its tooltip; selected, a failed row keeps its red tint and takes a 2 px accent outline inside it, so it stands out among failed rows), so the Workflow that names the run stays readable. Rows are marked for actions on many at once on Runs (Re-run, Remove) and on Decisions (Remove, decided gates only: a waiting gate is never marked, and is decided only in its detail): Cmd/Ctrl+click or X on a focused row marks or unmarks it, Shift+click marks from the last one marked, a plain click or Escape clears the marks; a marked row has an accent edge and a lighter tint, apart from the selected row, and is read as "marked"; right-clicking a marked row offers the actions for all of them ("Re-run 3 runs", "Remove 3 runs", Unmark all), one confirmation for a removal, and the notice counts them ("Started 3 runs"). Row hover tint, selected row accent tint.
- Spacing: 8/16/24. More space above a heading than below. The one exception is a status line, whose items sit 6 px apart around the "·" separators, so a line fits the 512 px detail column even with a classic scrollbar.

## Components

- Buttons: 32px, radius 6, 500 weight. Primary = accent fill; secondary = panel with line border; danger = red text, red border on hover. Disabled 50% with tooltip explaining why; a disabled field looks and explains itself the same way.
- Stored text and prompt views use one fixed-width 42 px button labelled `TXT` or `MD` for the current mode. Markdown is the default. The selected mode is one global UI preference that follows the operator across agents, pages, and reloads. It toggles in place between whitespace-preserving plain text and rendered Markdown without moving surrounding controls. JSON documents remain code and do not show the toggle. In Agents and Policies, Markdown mode previews the current editor text and switching back restores the same editable field.
- Inputs: 32px, radius 6, line border, accent border on focus, 2px focus ring outside. A field is as wide as its text (value, chosen option, or placeholder) and grows while typing; an empty name field in a form (New agent, New policy) starts at 200 px; only fields in a dialog and the trace ID field have a fixed width. Every field in a panel or dialog has a visible label; only the "Acting as" chip and the trace search are named by their placeholder, a field under a mode switch or a disclosure is named by it, and a select whose options name themselves ("Last 100 lines") needs none. Timeout and Retries keep a short fixed width. A placeholder or an empty option shows the default or names the empty state ("2m", "No tools", "No agent", "Not set"), never an instruction. The Service field shows no suggestion arrow; its suggestions open while typing. Editable files keep the tinted block; the border darkens on hover and turns accent on focus.
- Segmented controls (the Runs status, Decisions' All/Waiting/Decided): 3 px inside a 1 px line, 26 px options 3 px apart with 12 px side padding, radius 9 outside and 6 inside; the chosen option on the panel colour with a small shadow. An option never touches the edge.
- Step tile (canvas): 220×64, radius 8, panel fill, 1px line, no coloured bar or edge stripe: the outline and the icon name the kind of step. The icon is muted, violet only for a step that waits for a person (gate, interactive session). Row 1: name 14/600. Row 2: agent ref or question, 12 muted, one line, ellipsis. Selected: accent border 2px. A tile is read as "Step Build: Inner v1", by the name it shows; keyboard focus draws an accent ring 4 px outside it, apart from the selection.
- One graph everywhere: the Workflows editor, the Runs detail and Overview draw a workflow with the same tiles, outlines, arrows and back edges (WorkflowGraph.drawGraph, graph.js); only the editor adds moving, connecting and menus. In a run, a tile's second line is its state, a filled dot and the state's word (hollow for Blocked), and its outline takes the state colour; the subtitle is then its tooltip. A read-only graph never shows the Input node.
- Tooltips: an icon button's tooltip is its name ("Copy trace ID", "New workflow"). Every other tooltip describes what happens or what is shown, in the third person ("Copies Intake with all steps and positions"), with no trailing period; a disabled control's reason too, never an instruction ("Needs an input text", "Needs your name in the top bar"). A tooltip never repeats visible text: text that can be cut off (table names and their headers, status lines, tree labels, canvas tiles) shows in full on hover only while it is cut off, and a status chip has one only to give a reason. A dialog title names the action and the kind ("Rename agent"), not the value its field shows. A gesture is named after what it does ("Draws a channel from Lead when dragged onto another member", "…; a double-click or Enter edits it"), never as an order ("Double-click to edit", "Drag onto…").
- Trees: every folder has a triangle, pointing right when closed and down when open, even when it holds no subfolders; folders start closed; a click on the open, selected folder folds it.
- Status chip: dot + word, 12/500, tinted background of the state at 12% alpha.
- Empty state: a short title only, optionally one button, centered in the panel. No sentence. Every page has one, worded alike ("No runs yet", "No decisions yet", "No agents yet" with New agent); a Blobstore folder that holds only folders shows "No files". A panel that cannot load shows the reason in red in the same place, once per page; Retry only on the editors (Workflows, Agents, Policies), since the live pages try again on their own.
- Dialog: 440 px for every small dialog (one field, one choice, or one question); Select Inputs is 720 px; 24px padding, title 24/600, body, footer with Cancel and one primary. No close button: Cancel, Escape, or a click outside closes it. Dialogs are anchored near the top, so a dialog that changes height grows downwards instead of moving its title. A disclosure inside a dialog uses the tree triangle and, when open, does not repeat what the field below it shows. Focus starts on the first visible field or the enabled primary button, stays inside the dialog (also when a mode switch redraws it), and returns afterwards; in a confirmation, Cancel has the focus so Enter never deletes.
- Notice: one short line bottom-centre. A confirmation fades out after 2 s; an error stays 6 s in red. Undo is Cmd/Ctrl+Z, never a button: it undoes the last delete, removal, or arrange on the Workflows page, only there and only until the next edit. Nothing else notifies. An undone edit is unsaved like any other edit until Save. A new workflow is a draft until its first Save: it is on the page only, so creating it shows no notice and never an error, Save is disabled until it has a step, and Run workflow… is disabled with the reason as its tooltip.
- Whatever is created opens: a new entry, a duplicate, an uploaded file. Duplicate means the same on every page: the copy is stored at once beside the original ("<name>-copy"), opens, and the notice says Duplicated. Every delete or removal that Cmd/Ctrl+Z cannot undo asks first, a single file or decision included. Deleting or removing the selected item selects its neighbour on every page: the next one, else the previous one, in the same group when there is one (a deleted group hands over to the entry after it). Deleting a Blobstore collection, or removing the last run in Blobstore, opens its parent folder.
- Actions live in right-click menus (canvas, nodes, every left sidebar: New, Rename, Duplicate, Delete where allowed); the keyboard opens the menu of what has focus with Shift+F10 or the ContextMenu key, under its left edge (the canvas takes focus for its own menu), and moves through it with the arrow keys, Escape returning focus to it. A step's menu has Connect to… (not on a router): a dialog listing every other step, checked when it receives this step's output, a step that cannot (a cycle, a router or workflow step that has its one dependency) disabled with the reason beside it; Apply makes it one edit, which Cmd/Ctrl+Z undoes. They are grouped by scope with a separator between scopes: actions on the clicked item first (on the canvas Run workflow…, then Add step and Auto-arrange, then Rename and Duplicate), then its Delete or Remove, then list-wide actions such as Clear runs or Clear decisions (on every row as well as on the sidebar), and the New items always last. Right-click outlines the row the menu acts on and never moves the selection (on the canvas a node is selected, as in drawing tools); live pages do not redraw while a menu is open, so the outline stays; a row without actions shows no menu at all, not the browser's; Escape closes a menu. After a menu item, or a dialog it opened, focus is back on the row the menu acted on. Workflows, Agents and Policies rename through Rename…, whose Group and Name fields also move an entry into another group. No action buttons in panel headers except "+", icon toggles, and Save in the Workflows canvas head (the page's one primary button).
- Keyboard shortcuts (shortcuts.js), never while a field, a dialog or a menu has the keyboard, and without modifier keys: G then a letter goes to a page (O Overview, M Metrics, C Cluster, W Workflows, A Agents, R Runs, E Evals, D Decisions, S Sessions, N Connectors, P Policies, K Skills, B Blobstore); R presses Run… on Workflows, or says why it cannot ("Not started: needs the workflow saved first…"); J and K open the next and previous waiting decision in the order Decisions lists them, wrapping around ("No decision waits" without any); / focuses the trace ID jump in the top bar; ? lists them all in a dialog, each key as a key cap. Enter opens a focused row or tile, and Cmd/Ctrl+Z undoes, as before.
- Canvas: the view is centred once per workflow (a graph wider than the canvas starts zoomed out until all of it fits, down to a quarter size, so no tile is cut off), then only pan (a drag on the empty canvas, or Shift+drag anywhere) and zoom (wheel) move it, remembered per workflow; the canvas shows a grab cursor. A click selects a node; a double-click opens only a workflow node, showing the workflow it runs, and expands nothing else. An arrow that skips a row never crosses a tile: it turns aside in the gap under its source, runs down the free channel beside its source column (on the side of its target; within one column, left of the leftmost column and right of any other), and turns back in the gap above its target, a little further out the more rows it skips; fitting the graph to the canvas keeps those lanes in view. An arrow to a step in the next row more than a column aside never runs as one diagonal across the gap: it goes down into the gap, along it, and down into its target, with rounded turns, arrows from different columns a few pixels apart. An arrow to a step beside its source, in the same row, leaves the side of the source tile and enters the facing side of the target instead of the bottom and top ports, so it runs behind neither tile; with other tiles in between, it passes under them through the gap below the row. A click on an arrow removes that dependency (Cmd/Ctrl+Z restores it), as does Remove dependency in its menu. Ports are muted and turn accent on hover; a port's tooltip says what flows through it (a first step receives the run input, a route step the one output that names the next workflow); a Route tile has no output port, since nothing may depend on it, and a drop the orchestrator would refuse (a cycle, a second input into a route step) is rejected at once with the reason as a notice; a refused save names steps and workflows in title case; the Input tile is plain, neither a step colour nor a state colour. A gate tile has a second output port, Rejected, outlined in the failed colour, on its right edge 20 px below the top: clear of the output port at the bottom middle and of the arrows that enter a tile's side at its middle. Dragged onto an earlier step it sets where the gate's rejections go (`on_reject`); the allowed steps are agent, interactive, team and workflow steps the gate depends on, directly or through others, and a refused drop gives the reason as a notice (not a step the gate depends on, a kind that cannot take a rejection, a merge or batch that would receive a result twice, a dev pod step that would run again). The back edge is a dashed arrow in the failed colour from the port to the target's side, at the port's height: straight lines with rounded corners that run beside the tiles in the free channel between two columns and, when a tile stands in the way, through the gap above or below a row, never across a tile. A click removes it (Cmd/Ctrl+Z restores it), as does Remove back edge in its menu; its tooltip says what goes back. An agent step whose agent version no longer exists has a red outline and reads "Missing: <ref>" in red, with the reason as its tooltip; its Agent select marks it (missing), and the node panel says "<ref> no longer exists" where the prompt would be, never a load error. The node panel has an icon toggle and is open by default.
- Node panel: header is the node type (Agent, Human Gate, Router, Service), centred. One row: Node ID, Agent, Service, Timeout (default 2m for an agent step, 10m otherwise), Retries (default 0); the last two right-aligned and wrapping together, every field sized to its content. Gates and routers have no Timeout or Retries, as they run no activity. A merge or batch node has Node ID, Sources (the steps it depends on, in their order, as read-only text: arrows change them, as for every step; "No sources" in muted text while it has none), Service, and its parameters, and no agent, question, Timeout or Retries: a merge has Capacity (default 16) and Input timeout (default 300), a batch Size (required, "Not set" while empty) and Input timeout (default 300). The parameters are plain digit fields without spinner arrows whose placeholder is the default; Input timeout is in whole seconds and shows the unit "s" beside the field. A step whose Service changes to or from merge or batch drops the fields that do not belong to its new kind. What the orchestrator would refuse on Save shows under the fields in red, one sentence each, like a team's problems (a node without a source, a batch without a size, a number that is not a whole number of 1 or more, a router that follows a merge or batch); Save is not blocked by them, since the orchestrator decides. A gate has Rejections go to (a select of the steps a rejection may go back to, nearest first, with "Nobody: a rejection ends the run"; a target that is set but not allowed is listed as "(not allowed)" and named in a problem) and, only with a target, Max rejections (a digit field, default 5). A dev pod node has Node ID, Repository (a select of the Connectors page's Git repositories; one that is gone is listed as (missing)), Source branch (a chosen repository brings its default branch), Work branch (default `agent/{run}`), Name (optional; its tooltip explains the reuse of a live pod), Service, and on full-width rows Protected paths (one glob per line) and Rules (a small list editor: Tool, Path, Matches, Message, a remove button per rule, "+" adds one; "No rules" while empty). A command node has Node ID, Service, Timeout (default 10m), the tickbox Allow failure, and the Command on a full-width row in mono that wraps and grows like a gate's question. A stop dev pod node has Node ID and Service only. Their problems show like the others (no repository, no source or work branch, a work branch equal to the source branch, a second dev pod step, a dev pod after a merge or batch, a rule without a tool or message or with a broken pattern, an empty command, a command or stop step that does not come after the dev pod step, a back edge the orchestrator would refuse); a step whose Service changes to or from these kinds drops the fields that do not belong to its new kind. A workflow step has a Workflow select and, beside it, a Version select (`v3 (newest)`, `v2`, `v1`); the step stores both as one pinned reference, `name@vN`, a newly chosen workflow starts at its newest version, and a pinned version that no longer exists is listed as (missing). A gate question gets its own full-width row, wrapping and growing with the sentence (one line is as tall as an input); Enter finishes it. Then "System prompt (systemprompt.md)" in full in a tinted block with a View agent link, and "Config (agent.json)" pretty-printed. No Inputs row, no Delete button.
- Names: workflow, node, agent, policy and skill IDs are shown in title case ("Small Fix") everywhere, the Agents, Policies and Skills trees included (the stored ID is the row's tooltip), and the factory's acronyms stay in capitals however the ID was typed (AI, API, CI, CLI, CSS, ECC, HTML, HTTP, ID, JSON, LLM, MCP, PR, QA, SQL, UI, URL, UUID, YAML: "ecc/ECC-plan" is ECC / ECC Plan, an error sentence starts "LLM gateway", never "Llm"); a group typed as it is shown is the existing group, and a rename that only changes the case of a name keeps its ID, so showing an acronym never moves a workflow; tooltips, notices, and the Node ID field included; stored IDs are unchanged, and a typed name is saved as an ID: lowercase words joined by dashes, except a word typed in capitals, which stays in capitals ("API Review" is saved as API-review and shown as API Review); a group is saved part by part. A grouped workflow reads with its groups wherever it is named outside the Workflows tree ("ecc/ECC-plan" as "Ecc / ECC Plan"), in pick lists, tiles, notices, and the Runs and Decisions sidebars alike. Names that differ only in case count as the same name. Blobstore shows object names as stored, since they are the blobstore keys, run folders included (their trace IDs). A run has no name of its own: tables and pick lists call it by its workflow (or, without one, its shortened trace ID); where a run is picked from a list, its start time follows ("Workflow · time").
- Motion: 150–200ms ease-out on panel and menu reveal; running dot pulses; nothing else moves. A column shown by its toggle (sidebar, detail, node panel) arrives from its own edge of the window; hiding it is immediate. With reduced motion, nothing animates except the notice fading; those rules are the last ones in the stylesheet so that they win.

## Forbidden

Monospace for labels; uppercase tracked eyebrows; coloured top or side bars on tiles, cards, or rows (removed from the canvas tiles on 17 Nov: they read as generated); cards inside cards; explanatory sentences under controls (tooltips carry explanations); UUIDs as the primary label of anything; two primary buttons on one screen; any color as the only carrier of a state.

## Selection and empty detail

- A list–detail page never shows an instruction in the detail area. On load, the newest or last-used item is selected automatically and its detail is shown; a remembered or linked item that no longer exists gives way to the newest one, never a ghost detail (in Cluster a gone pod gives way to its deployment, since pods are renamed on every restart; in Decisions a linked decision is shown or nothing is, and no other decision ever takes its place, because Approve and Reject act on what is shown). Within a session, a page's menu item returns to where that page was left; on the page itself it opens the page plainly. Only a truly empty list shows the empty state, in the panel that holds the list, with at most one button.
- Column widths start the same on every page, Blobstore included: sidebar 260 px, detail column 512 px; the middle takes the rest. Every panel header is 48 px. A resized column keeps its width per page. When the middle column is narrower than about 420 px, the Runs status buttons become a dropdown. On a narrow window the side columns give way first (the sidebar down to 200 px, the detail down to 320 px) so the middle keeps 420 px as long as it can; from 1192 px on, every column has its set width. The menu is never cut off: when it does not fit between the logo and the chip (the two count badges included), it gives way in steps, only as far as it must: tighter spacing, then the product name (the logo stays), then the icons of the other pages, and at last the other pages show their icon alone, named by its tooltip. The active page keeps its icon and label at every width. In a detail column under 440 px, the meta line wraps without its dots and the Runs steps drop the agent.
- Every page has the same structure: a sidebar (tree or list), a middle column, and a detail column on the right. The panel-header row carries the toggles at its right end: the sidebar toggle, then page toggles, then the detail toggle. Workflows: tree, canvas, node panel. Runs and Decisions: workflows, a table, the selected item. Sessions: sessions, chat and file tabs, the session's files. MCP Gateway: services, the three configuration files, quick testing. Blobstore: folders, objects, the object. Agents and Policies: tree, the selected version. Connectors: the connector kinds (Git only), then the kind's content. Cluster: tree, the selected item.
- Connectors: the middle shows two tables under section titles, edge to edge. Repositories: Name, Kind (Plain, GitHub), URL, Default branch (gives way first), Access ("Read", "Read and write", "No credential"). The URL opens the repository in a new tab. Built-in repositories open through the Factory Git Host browser. Clicking the rest of the row opens Edit repository, the "+" in the header opens New repository, and the row menu has Edit…, Delete (asks first), New repository. The form is a 440 px dialog: Name (fixed once stored), Kind, URL, Default branch (placeholder main), Setup command, Idle minutes (digits, placeholder 30), the tickbox "Ask a person before publishing" (ticked for a new GitHub repository until changed by hand), Access, and Token. The token is write-only: a password field that always starts empty, reads "Unchanged" while a token is stored, is disabled without a credential, and is never shown anywhere; an empty field keeps the stored token. A field's problem shows under it. Dev pods: State (the Cluster chips), Repository (with the pod's name in brackets), Work branch, Runs (links to Runs, named like runs elsewhere; gives way first), Expires ("Held by a run" while an open run uses it, else whole minutes), then View files and Destroy; Destroy asks first, says that unpushed work is lost, and confirms with Destroyed. The pods are read again every 10 s. Empty tables read "No repositories yet" and "No dev pods".
- Dev pod view: opened with View files from Connectors and from a run; it has no menu item, and Connectors stays the active one. It is read-only. The sidebar is a tree: "Diff against <source branch>" (shown first), "Commit log", then the pod's folders and files (folders first). The content shows a status line (state, repository, work branch) and the chosen item: a file as code (Markdown with the TXT/MD toggle, JSON pretty-printed), the log as git prints it, the diff with additions and removals tinted (the + and - still say which). The choice travels in the hash, and what is shown is read again every 10 s. A pod that is gone reads "This dev pod no longer exists", nothing else.
- MCP Gateway: the sidebar lists passthrough service names and offers New and Delete through the same `+` and right-click patterns as the other editors. The middle column edits `mcpconfig.json`, `allowlist.json`, and `denylist.json` in tinted monospace blocks with one Save action. The right column has Test connection, an allowed-tool select, JSON arguments, Send, and the full formatted JSON result. It is a quick configuration check, with no histories, saved requests, dashboards, or direct upstream access from the browser.
- Workflow versions: nothing in the editor is saved automatically. Graph edits, moved nodes included, stay on the page until **Save** in the canvas head stores them as the next version of the workflow; stored execution graphs never change (version descriptions have a separate in-place save), and the notice says "Saved v4". The canvas head's one primary button is **Run…** while the canvas shows a stored version without unsaved edits: it opens Select Inputs for that version (its tooltip, "Opens Select Inputs to start runs of v3"; disabled with the reason when the workflow has no step). The first edit turns it into **Save**, in the same place, and keyboard focus stays on that place; Save is enabled only with unsaved edits; disabled, its tooltip gives the reason ("No unsaved edits", "Needs a step"), enabled, the version it stores ("Stores the workflow as v4"); once stored, the button is Run… again. A draft shows Save. Left of it, the canvas head has a version select, newest first (`v3 (newest)`, `v2`, `v1`), named by its options; the newest version is shown by default, and the hash carries `?version=N` only for an older one, so a reload returns to it. An older version reads "Viewing v2" beside the select until it is edited, then "Edited v2: saves as v4": Save never changes v2. A new workflow reads "Not saved yet" and has no version select; its first Save stores v1. Unsaved edits survive selecting nodes and a visit to another page; another workflow, another version, a workflow node opened by a double-click, or a link to any of them asks "Discard your unsaved changes?" first, and keeping the edits puts the hash back; leaving the site asks through the browser. A draft left without a step is gone without a question. Runs started from the editor use the version on the canvas; with unsaved edits (or a draft) Run workflow… is disabled with the reason, and a click on the Input node says "Not started: needs the workflow saved first". ## UI antipatterns from the Evaluations implementation

These are observed mistakes, not optional styling preferences. Apply their corrections to every affected page.

| Antipattern we shipped | Required behavior |
| --- | --- |
| New selects used browser defaults while adjacent buttons and inputs were styled, leaving Safari controls different heights and labels misaligned. | Reuse the shared control treatment. Inputs, selects, and buttons are 32 px high, border-box, with consistent typography, borders, label spacing, and alignment. Apply explicit Safari-compatible select appearance and arrow styling. |
| Workflow and Agent were text fields with datalist suggestions when the user expected selectable options. | Workflow, Agent, and Status are dropdowns. Preserve selected values when options refresh. |
| Runtime filters were as wide as long text fields. | Fit expected values: compact fields sized for roughly four digits, without imposing an arbitrary four-digit data limit. |
| Runtime fields showed “Any” and native up/down steppers. | Plain digit-entry fields, no spinner arrows. Use numeric placeholders and a visible `s` unit. Empty means no bound; a placeholder is not a submitted value. |
| Duration labels said “End-to-end min (s)” and “End-to-end max (s)”. | One group label: **Runtime From/To**. Two compact inputs; accessible labels distinguish From and To. Explain seconds in the unit and tooltip. |
| Date labels included the unnecessary annotation “(local)”. | Use **Started after** and **Started before**. Preserve correct timezone conversion without extra label clutter. |
| Oversized controls pushed Apply onto an isolated row. | Size controls by their content, align all field bottoms, and wrap deliberately at narrower widths. Do not stretch short numeric inputs to fill space. |
| A new page was placed by implementation convenience instead of the requested navigation. | Keep each page in its named navigation group. Change grouping only when the operator requests it. |
| Refresh appeared as a text button, and the model name was repeated below its selector. | Refresh is the shared icon button with an accessible name and tooltip. Display the model name once. |
| Input datalist references were assigned to the read-only DOM `input.list` property, preventing the whole page from registering. | Set read-only reflected properties through attributes. Test actual DOM constraints, not only permissive mocks. |
| Passing API/unit tests was treated as proof that the page loaded and looked correct in Safari. | Verify page initialization, navigation, alignment, wrapping, and interaction in the target browser when available. State any browser-verification gap explicitly. |

### Delivery checks for UI changes

Workflow descriptions belong to a specific workflow version and can be edited in place without creating a new version. Show the selected version's description as a compact text-only footer below the graph, showing only the description text. No `Description:` prefix, heading, edit icon, separate line, or action buttons. Double-click (or keyboard Enter) edits only the text, with no `Description:` prefix. Enter or blur saves in place; Escape cancels. Descriptions are single-paragraph strings: flatten pasted line breaks and wrap naturally at word boundaries, with height determined by the wrapped text. Description edits never enable the graph's version Save or discard graph edits. In Runs, hovering a workflow name shows the current description of the exact version that run used; never substitute the newest version for a run whose version is unknown.

Connections inside a Teams node are communication channels, never workflow sequences. A channel must have at least one agent endpoint. Refuse workflow-to-workflow links on both click-to-connect and drag-to-connect, with a clear reason and no graph mutation. Workflow results return to the agent that requested them; the agent can send a result to another workflow. Existing invalid links remain removable in the editor.

1. Read this guide before changing UI. Reuse existing controls and layout conventions.
2. Check adjacent controls as a group, not only the edited control; keep the same height, spacing, typography, and interaction states.
3. Check Safari and Chrome behavior, normal and narrow panel widths, and keyboard accessibility. Add behavioral regressions where a browser mismatch caused a failure.
4. Deploy the changed factory UI and verify the live files match the tested version before reporting it deployed.
5. Record new user corrections here rather than inventing new patterns or repeating these mistakes elsewhere.


### Agent policy references

The system prompt filename is `systemprompt.md`. Agent settings include a compact **Policies** multi-select dropdown, styled like the other 32 px controls. Its selection reflects `{{policy::policyid}}` references in the prompt. Adding a missing selection appends that reference to the draft, opens text editing, and reveals the existing Save-as-new-version action; it never saves immediately or duplicates an existing reference. Deselecting removes only the matching template reference from the draft, preserving surrounding prose.

The prompt context menu also offers **Add policy**. Insert the selected reference at the captured cursor/selection; cancelling changes nothing. Both paths use policy IDs from the policy service. Validate references before confirmation/save and show a precise inline error while retaining the draft. The registry validates again, and the agent resolves policy content through the policy service on each run. Stored prompts retain their template references.

## UI antipatterns from the Runs execution panel

- **Duplicating metrics:** the implementation repeated each attempt's token counts and processing time in a summary block and again in event rows. Record metrics in the backend; show them once in the selected event's evidence. Do not place timing/token summaries above the event list.
- **Turning a detail panel into a telemetry dashboard:** showing status, step, attempt, model, duration, token counts, and error category in every row produced a wide, noisy table. Default rows contain only status, step, and event. Show attempt numbers only when retries need disambiguation. Model names and metrics belong in selected-event details.
- **Solving overflow by adding clutter:** wrapping every metric onto additional rows makes the panel taller without making it clearer. Remove redundant information first, then use a compact responsive layout that fits the normal 512 px detail panel and narrower resized panels.
- **Repeating failure information:** a failed call and an identical “Attempt failed” row should not repeat the same failure. Show a separate terminal failure only when it adds information, such as an artifact-write failure or an attempt with no recorded event.
- **Instructional filler:** “Select an execution event to inspect its evidence” is not content. Keep the evidence region hidden until it has meaningful selected-event content; use ordinary selectable-row affordances.
- **Claiming visual quality from unit tests:** passing tests does not prove hierarchy, density, wrapping, or Safari rendering. Inspect the rendered panel when browser control is available and explicitly report any visual-verification gap.

These rules apply across the factory. More collected evidence must improve investigation, not increase the default information density. Re-run belongs in the run row's right-click menu; it starts the workflow version the run used (the newest for a run that recorded none) with the original input as a new run and opens that run. The steps of a run are read from the versions it used: its own and those of its nested workflows.

### Resizable tables

Do not make only the first column absorb panel resizing. That happened in Blobstore because the shared name cell used `width: 100%` while other columns stayed content-sized. Blobstore uses proportional columns across the available middle-panel width; resizing either divider redistributes Name, Creator, Created, and Size together. At narrow widths the optional Creator column disappears and the remaining columns redistribute the width. Headers and rows stay aligned, clipped content remains available on hover, and the table never forces horizontal panel overflow.

### Inspectable execution evidence

The workflow canvas context menu keeps its creation of agent, human gate, interactive session, child workflow, team, router, custom service, merge, batch, dev pod, command, and stop dev pod nodes in one Add step submenu, so the menu itself stays short: Add step (ending in ›) opens the twelve in the menu's place, by click, Enter or ArrowRight, with "‹ Add step" first to go back (click or ArrowLeft); a menu has at most one level of submenu. Adding a draft node creates no dependencies or arrows. Preserve existing step arrows and the Input arrows of saved roots.
